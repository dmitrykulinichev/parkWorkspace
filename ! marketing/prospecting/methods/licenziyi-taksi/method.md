# Метод: реєстр ліцензій на таксі (Укртрансбезпека) + авто ліцензіатів

| | |
|---|---|
| Джерело | відкриті дані Укртрансбезпеки: API `middleware.dsbt.gov.ua/api/opendata/lc_licenses` (живий) + data.gov.ua: «Транспортні засоби, як засоби провадження господарської діяльності» (останній файл 18.02.2022) і «Реєстр ліцензій на … таксі» (02.08.2024) |
| Гіпотеза | Легальні парки мають ліцензію на таксі. Реєстр дає ЄДРПОУ/ІПН, а реєстр ТЗ — скільки легкових авто в кожного й де вони зареєстровані. Це офіційний список парків з розміром, навіть тих, хто ніде не рекламується |
| Версія | 1.1 (2026-11-18): новачки (перша ліцензія таксі з 2025), «ПП + ПІБ» = фізособа, локальна таблиця `registry/licenses_taxi.csv` |
| Файли | `collect.py` (завантаження), `merge.py` (злиття), `build_table.py` (локальна таблиця всього реєстру) |
| Сирі дані | `_raw/<дата>_licenses/`: `api_pages/NNNN.json`, `vehicles_2022-02-18.zip`, `reestr-taksi_2024-08-02.xlsx` |

## Як працює
1. `collect.py` завантажує всі сторінки API ліцензій (~953 по 100, пауза 0,7 с, після обриву продовжує) і два файли data.gov.ua.
2. `merge.py`:
   - бере чинні ліцензії з видом діяльності «…таксі»;
   - до кожного ЄДРПОУ/ІПН додає легкові авто з реєстру ТЗ 2022 (типи «Легковий», «_Легковий», «Таксі»; унікальні номери):
     кількість, область за літерами номера (AA/KA = Київ, BC/HC = Львів…), моделі, роки випуску;
   - склеює з реєстром клієнтів: ФОП — прізвище + ініціали (+ та сама область), ТОВ — нормалізована назва;
     знайденим дописує ключ `lic:<код>`, `к-сть_авто` (якщо порожня) і відмітку в нотатки.

## Правила відбору
| авто (2022) | рішення |
|---|---|
| 1 | лише `seen` (водій-одинак) |
| 2 | B, мікропарк |
| 3–15 | **A**, наш сегмент |
| 16–30 | B |
| > 30 | C (орієнтир) |
| немає даних, ТОВ/підприємство | B «розмір невідомий» (ліцензія після 2022) |
| немає даних, ФОП | лише `seen` |

Телефонів у реєстрі немає, тож нові записи мають стадію «не перевірено» й наступну дію «знайти контакт за назвою / ЄДРПОУ»
(Google, OLX, Work.ua, Opendatabot).

## Новачки (v1.1)
Новачок = перша ліцензія на таксі з 01.01.2025 (на 2026-11-18: 1 289 з 9 649). Даних про авто в них немає (реєстр ТЗ — 2022).
- ТОВ-новачок, що займається лише легковими (таксі / «на замовлення») → **A** «новий ліцензований перевізник» (новий бізнес, ще без софту);
- ТОВ-новачок з автобусами/вантажами → B (таксі — побічний напрям);
- ФОП-новачок → B «новачок-ФОП» (1 147 з 1 289 новачків взяли ще й «на замовлення» — часто це водій сам на себе).
У нотатках таких записів — «НОВАЧОК (перша ліцензія таксі ДД.ММ.РРРР)».

## Локальна таблиця реєстру: `registry/licenses_taxi.csv`
Увесь реєстр (усі 9 649 чинних ліцензіатів, і водії-одинаки теж) — щоб повертатися без повторного завантаження.
`python -I prospecting/methods/licenziyi-taksi/build_table.py prospecting/_raw/<дата>_licenses` (після merge.py).
Колонки: код, назва, тип, перша_ліцензія_таксі, новачок, дати, інші види, авто_2022, місто/область за номерами, моделі, роки,
`client_id` (точний збіг), `можливий_збіг` (кандидати для ручної перевірки — НЕ склеюються автоматично).
2026-11-18: з 5 кандидатів підтверджено вручну 3 (ТОВ «Таксі 6000»→№770, Турчак→№531, Сліпецький→№429), 2 відхилено.

## Як відтворити
```
python -I prospecting/methods/licenziyi-taksi/collect.py prospecting/_raw/<YYYY-MM-DD>_licenses      # ~15 хв
python -I prospecting/methods/licenziyi-taksi/merge.py   prospecting/_raw/<YYYY-MM-DD>_licenses --dry-run
python -I prospecting/methods/licenziyi-taksi/merge.py   prospecting/_raw/<YYYY-MM-DD>_licenses
```

## Обмеження
- Реєстр ТЗ — станом на **лютий 2022** (набір «не оновлюється»): кількість авто могла змінитися, а в нових ліцензіатів даних немає.
- Регіон береться з номера авто, тобто з місця реєстрації, а не з місця роботи.
- Багато парків працюють без ліцензії (через агрегатори, ФОП водіїв). Реєстр показує лише легальну частину ринку.
- Склейка ФОП за прізвищем та ініціалами може зрідка помилятися при однакових прізвищах в одній області. Сумнівні збіги
  перевіряємо вручну.
