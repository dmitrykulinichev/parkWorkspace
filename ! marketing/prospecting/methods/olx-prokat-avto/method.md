# Метод: OLX «Прокат авто» → продавці з кількома авто

| | |
|---|---|
| Джерело | OLX.ua, категорія Транспорт → Прокат авто (`category_id=3440`) |
| Гіпотеза | Власник, у якого 3–10 активних оголошень оренди, — це малий парк, що здає авто водіям (часто під таксі) |
| Версія | 1.3 (2026-11-17). Зміни: 1.3 — телефони, написані власником у тексті оголошень; 1.1 — «Chevrolet Bolt» більше не рахується як згадка Bolt-таксі; 1.2 — великі таксі-парки (>15 оголошень) теж ідуть у реєстр як C «орієнтир», колонка `де_рекламується` |
| Файли | `collector.js` (збір у браузері), `merge.py` (злиття в реєстр) |
| Сирі дані | `prospecting/_raw/<YYYY-MM-DD>_olx-prokat-avto.json` |

## Як працює
1. **Скан.** Для кожного міста з `CONFIG.cities` проходимо публічний JSON-API OLX
   `/api/v1/offers/?category_id=3440&city_id=<id>&offset=..&limit=50`. З кожного оголошення беремо `user.id`
   і рахуємо, скільки оголошень у кожного продавця.
2. **Профіль.** Для продавців, у яких у скані ≥2 оголошень: `/api/v1/offers/?user_id=<id>&limit=50`, тобто всі
   активні оголошення продавця. Рахуємо:
   - `rent_ads`: оголошення в категорії прокату ≈ кількість авто;
   - `taxi_hits`: скільки з них згадують таксі/Uklon/Bolt/Uber;
   - `buyout`: чи згадується викуп або розстрочка;
   - назви, райони, посилання на оголошення і профіль.
3. **Відбір і злиття** (`merge.py`): кандидат, якщо хоч одне оголошення згадує таксі/Uklon/Bolt/Uber **і** `2 ≤ rent_ads ≤ 15`.
   Без згадки таксі це переважно весільні, VIP і туристичні прокати: у реєстр не йдуть, але потрапляють у `seen.csv`.
   Пріоритет A: `3 ≤ rent_ads ≤ 10`; B: 2 або 11–15; C (з 1.2): > 15 і згадує таксі — великий парк, орієнтир для дослідження ринку, без дати першого контакту. Дублі відсіюються за `ключ_джерела = olx:<user_id>`.
4. **Журнал переглянутих** (`registry/seen.csv`): кожен продавець зі скану, також і відсіяні, записується з
   `вперше / востаннє / оголошень_востаннє / рішення / client_id`. Це відповідає на питання «чи бачили ми вже цього
   власника?». Відсіяних раніше `merge.py` щоразу переоцінює (власник міг вирости).

**Ідентифікатор власника:** `olx:<user_id>`, тобто числовий ID акаунта продавця на OLX. Він не змінюється, коли
оголошення оновлюються чи видаляються. Профіль: `https://www.olx.ua/uk/list/user/<user_id>/`.
Один власник на різних майданчиках (OLX, Work.ua…) матиме різні ключі. Склеюємо їх вручну за телефоном,
коли телефон стає відомий: у `нотатки` пишемо `також: <інший ключ>`.

## Як відтворити (агент або людина)
1. Відкрити https://www.olx.ua/ у Chrome (логін не потрібен).
2. Виконати вміст `collector.js` у консолі сторінки. Агент робить це через `javascript_tool`, вставляючи файл повністю.
3. `g24olx.start()` запускає збір у фоні. Виклики інструменту агента обриваються через 45 с, тому не чекаємо
   в одному виклику, а опитуємо `g24olx.status()`, доки не буде `done: true` (≈10 хв на всі міста).
4. Вивантаження (через буфер обміну; результат ~сотні КБ, тому не через відповідь агента):
   - у консолі сторінки `g24olx.stage()`: кладе повний JSON `{config, started, finished, log, rows, sellers}` у текстове поле
     вгорі зліва і виділяє його;
   - натиснути **Ctrl+C** на сторінці (агент: дія `key ctrl+c` через `computer`);
   - у PowerShell з папки `! marketing`:
     `Get-Clipboard -Raw | Out-File -Encoding utf8 "prospecting/_raw/<YYYY-MM-DD>_olx-prokat-avto.json"`
   - перевірити, що файл парситься і кількість `rows`/`sellers` збігається з тим, що повернув `stage()`.
   (Варіант з `fetch` на локальний сервер 127.0.0.1 не працює: Chrome блокує доступ сайту до локальної мережі.)
5. `python -I prospecting/methods/olx-prokat-avto/merge.py prospecting/_raw/<файл>.json --dry-run` для перевірки,
   потім те саме без `--dry-run`.
6. Дописати рядок у журнал у `prospecting/sources.md`.

Повторний прогін (наприклад, раз на 2–4 тижні) безпечний: нові продавці додаються, наявні пропускаються.

## Обмеження та відомі нюанси
- Тільки через браузер: прямі запити до API без браузера (curl/Python) OLX відхиляє з 403 (перевірено 2026-11-17).
  Обходити цей захист не намагаємося.
- API віддає не більше ~1000 оголошень на один фільтр. У Києві оголошень більше, тому продавця, в якого
  **жодне** оголошення не потрапило в перші 1000, пропустимо. В інших містах цього обмеження не видно.
- `rent_ads` не дорівнює точній кількості авто: буває кілька оголошень на одне авто або одне оголошення на кілька авто.
  Точну цифру уточнюємо в розмові.
- Фільтр «згадано таксі» відсікає й тих, хто здає водіям, але слово «таксі» не пише (наприклад, «під доставку», «під особисті потреби»). Їх можна переглянути в `seen.csv` з рішенням «таксі не згадано».
- Номер за кнопкою «показати телефон» скрипт **не відкриває**, бо OLX захищає його від автоматизації. Беремо тільки номери,
  які власник сам написав у тексті оголошення (з 1.3). Але OLX **маскує** номери в описі (`09*******67`), тож на практиці
  телефонів з OLX немає (перевірено 2026-11-17: 0 з перших 57 профілів). Номер з'являється лише в чаті OLX або при
  ручному перегляді, а також через склейку з іншим джерелом (Work.ua, Robota.ua, Telegram) за назвою чи контактом.
- ID міст брались з `/api/v1/friendly-links/query-params/<slug>/` і перевірялись за `location.city.name`
  (наприклад, slug `nikolaev` веде на Миколаїв у Львівській області, тому правильний ID — 106, slug `nikolaev_106`).

- У прогоні 2026-11-17 (версія 1.0) до 8 кандидатів могли потрапити через «Chevrolet Bolt». Під час першого контакту
  це видно одразу; у версії 1.1 виправлено.
