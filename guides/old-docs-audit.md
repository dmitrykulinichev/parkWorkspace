## Принцип (рішення користувача 05.11.2026)

**Мета документації v2 — допомогти персоналу парку й водіям розібратися в софті.** Перша версія була
наповненням сайту, поки не працював блог; блог тепер — маркетинг про нові можливості й розвиток продукту.
**Документація — мінімалістична, чітко й ясно. Рекламне — в блозі.**
Кожна сторінка відповідає на три питання: *що це за сторінка* → *як зробити основні дії* → *що означають
статуси й поля*. Без «тримайте руку на пульсі», «що ви отримуєте», «стратегічні рішення».

## Загальний висновок

- **Усі 55 сторінок** (`landing/www/content/docs2`) написані в травні 2026 рекламною мовою, згенеровані з коментарів
  коду: розділи «Чому це важливо?», «Що ви отримуєте?», «Поради»; покрокових інструкцій немає.
  Висновок: **переписати всі**, а не латати по реченню. Рекламні тези, де вони цінні, — кандидати в блог.
- **Скріни** (104, `content/docs2/screenshots/light/`) — квітень 2026, Katalon. Кабінет відтоді змінився (бічне
  меню, дашборд, списки водіїв і авто, графік, ТО). Висновок: **перезняти всі** через `capture.mjs`
  (реєстр, як у лендінгу) — тоді й трьома мовами.
- **Технічний жаргон** у текстах для користувача: `CRUD`, `localStorage`, `allowPastEditing`, `SWAP`, `URL`,
  `UI Inspector`, «Uklon API», «пагінація», «Open / In Progress», «стейкхолдери», «з'єднання API».
- Після травня вийшло **35 статей блогу** про нові можливості — у документації нічого з цього немає.

## Нова структура (на погодження)

Структура = меню кабінету + застосунок + «Початок роботи». ✅ — сторінка є (переписати), 🆕 — немає.

**Початок роботи** 🆕 — перші кроки парку: авто → водії → запрошення водіїв (код парку, застосунок) → Uklon →
Telegram-бот → команда. Одна сторінка-маршрут з посиланнями.

| Група | Сторінки |
|---|---|
| Головна | ✅ Головна панель (віджети: що показує кожен, як налаштувати) |
| Водії | ✅ Список водіїв (+ 🆕 документи водія, запрошення й доступ до застосунку, копіювання в інший парк) · ✅ Призначення · ✅ Звернення · 🆕 **Залоги водіїв** |
| Графік | ✅ Графік роботи |
| Задачі | ✅ Задачі |
| Автомобілі | ✅ Автомобілі (+ 🆕 передача, історія передач, QR-наліпка) · ✅ ТО · 🆕 **Стан авто** (огляди) · ✅ Недоступності · 🆕 **Пробіг** · ✅ Документи (+ страховки) · ✅ Звіти · ✅ Налаштування (регламенти ТО) |

## Шаблон сторінки

```
# Назва (як у меню кабінету)

Одне-два речення: що на сторінці й навіщо.

[скрін сторінки]

## Як <дія 1>
1. …  2. …  3. …

## Як <дія 2>
…

## Статуси / поля        ← лише якщо є що пояснити, таблицею

## Див. також            ← 2–4 посилання на суміжні сторінки
```

Обсяг — до ~250 слів на сторінку. Скріни — лише ті, без яких незрозуміло (сторінка + 1–2 ключові форми), не кожна
модалка.

## Порядок робіт (пропозиція)

0. Попутно: виправити №19 у `landing-outdated-claims.md` (імпорт водіїв є).
1. Погодити структуру й шаблон (цей документ).
2. Скріни документації — у реєстр `capture.mjs` (окремий розділ реєстру або свій файл `content/docs2/screens.json`).
3. Переписати українською групами, починаючи з того, що найчастіше потрібне: Початок роботи → Застосунок для водіїв → Застосунок для персоналу →
   Водії → Автомобілі → Telegram (формат повідомлень) → Фінанси → решта. Кожна група: текст → скріни → перевірка.
4. Переклад en/ru — групами, у міру перекладу відповідних сторінок кабінету (`i18n-plan.md`).
