# Публікація статей блогу без кабінету

`publish.mjs` кладе статтю з теки в суперпарк (ендпоінти `/api/blog-publish/*` за ключем) — з картинками
й обкладинкою. Дивитись і правити статті — як і раніше, в адмінці суперпарку («Статті блогу»).

```
node blog/publish.mjs blog/drafts/driver-documents             # створити статтю
node blog/publish.mjs blog/drafts/driver-documents --sync      # + синхронізувати лендінг
node blog/publish.mjs blog/drafts/driver-documents --replace   # свідомо перезаписати наявну
BLOG_ENV=local node blog/publish.mjs <тека>                     # локальний суперпарк (тека лишається на місці)
```

- `drafts/` — статті, яких ще немає в суперпарку; `uploaded/` — історія завантаженого (скрипт переносить
  сам). Чинна версія статті — в адмінці суперпарку: тека в `uploaded/` — як було на момент завантаження.
  Завантажити заново — скопіювати теку з `uploaded/` у `drafts/` і запустити з `--replace`.

## Тека статті

- Назва теки — унікальний ключ статті, він же `slug` (латиниця, цифри, дефіси).
- `article.md` — frontmatter (`excerpt`, `tags` через кому, `status` draft|published,
  `published_at` — минула дата = заднім числом, майбутня = відкладена; `cover` — файл обкладинки),
  далі `# Заголовок` і текст у markdown.
- Картинки — файлами поруч, у тексті `![Підпис](card.png)`; скрипт завантажує й підміняє посилання.
- `<!-- … -->` — чернеткові позначки, на сайт не йдуть.

Скрипт разовий: лише створює статтю. Якщо стаття з таким ключем уже є в суперпарку — зупиняється, нічого
не змінивши, тож правки в адмінці не перезапише, поки сам не скажеш `--replace`.

## Налаштування

- `blog/.env` (не в git): `BLOG_PUBLISH_URL`, `BLOG_PUBLISH_KEY`; `.env.local` — для локального суперпарку.
- Суперпарк, `.env`: `BLOG_PUBLISH_KEY` (той самий ключ) і `BLOG_PUBLISH_AUTHOR_ID` — id користувача,
  який значиться автором статей і завантажувачем картинок. Без них ендпоінти відповідають 503.
