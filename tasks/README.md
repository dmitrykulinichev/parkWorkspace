# Задачі — стан сесії (для агентів)

Кожна задача — окрема папка `tasks/YYYY-MM-DD-коротка-назва/` (дата старту, назва латиницею
через дефіс, напр. `2026-11-04-drivers-search-focus`). Папку створює мозок на початку задачі;
якщо задача продовжується в новій сесії — працює в тій самій папці.

## Навіщо

1. **Перерватись і продовжити з нового чату.** Новий чат на «продовжуємо задачу <назва>» читає
   `plan.md` і `session.md` цієї папки й працює далі — без переказу попередньої розмови.
2. **Не тримати зайве в контексті чату.** Подробиці (що з'ясовано, проміжні результати, причини
   рішень) пишуться у файли, а в чат — лише короткий статус. До деталей повертаються читанням
   файлу, коли вони справді потрібні.

## Файли в папці задачі

- `plan.md` — план і його стан: мета (1–2 речення), кроки чекбоксами `- [ ]` / `- [x]`,
  поточний крок, відкриті питання. Оновлюється при кожній зміні плану чи завершенні кроку.
- `session.md` — файл сесії, історичний лог для утримання контексту: записи лише дописуються в кінець, старі
  не переписуються. Формат запису: `### YYYY-MM-DD HH:MM` + що зроблено, що з'ясовано, яке
  рішення прийнято й чому. Новий агент має відновити контекст задачі тільки з цих двох файлів.
- `hands.md` — журнал рук (агент, скрипти, тести, браузер, збірки, релізи): лише дописування,
  один запис на запуск — `### YYYY-MM-DD HH:MM · <хто: агент/скрипт/тести/браузер>`, завдання
  (1 рядок), результат (1–3 рядки), шлях до сирого виводу. Сирий вивід (повні логи тестів,
  дампи, скріни) — у `hands/` поруч, у чат і в `session.md` не копіюється. `session.md` тримає
  рішення мозку й посилається на записи `hands.md`, а не дублює їх.


## Завершення задачі

1. Короткий запис у ченджлог — за правилами `changelog/README.md`.
2. Одне речення — коментар для коміту: в кінці `session.md` (`### Коміт`) і у відповіді користувачу.
3. Коміти й пуші робить користувач сам — агент не комітить і не пушить.
