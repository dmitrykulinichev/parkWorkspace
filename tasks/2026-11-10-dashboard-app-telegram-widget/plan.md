# Віджет на Головній: водії без Telegram / без застосунку чи зі старою версією

**Мета:** на Головній кабінету — віджет: активні водії, не підключені до Telegram, і окремо — ті, хто не
встановив застосунок або має застарілу версію. Для цього — правильно передавати й зберігати версію
застосунку й ОС (iOS/Android) кожного водія (частково версії вже збираються в суперпарку).

## Схема (на погодження, 10.11.2026)

**1. Релізи застосунку (суперпарк).** Таблиця `app_releases`: `build` (унікальний), `version`, `released_at`,
`notes` — текст запису з `kmp/release/CHANGELOG.md` для цієї збірки (скрипт бере його з ченджлогу; користувач 10.11).
- Запис робить скрипт: `kmp/scripts/publish-android.mjs` (після публікації на production) і
  `publish-ios.mjs` (після відправки на рев'ю) → `POST /api/app-releases` з ключем у заголовку (як
  `CheckLandingApiKey`; ключ — у `.env` прода й локально в скриптах). Повторний виклик з тим самим build — без дублю.
- «Остання» = найбільший build у таблиці. `/version-check` теж бере `latest_build` звідси (env — запасний варіант).
- Відставання водія = кількість релізів у таблиці з build більшим за його build (а не різниця номерів).
- Початкове наповнення — міграцією з `kmp/release/CHANGELOG.md` (B-релізи).

**2. Версія застосунку водія.** Застосунок B шле на кожен запит заголовки `X-App-Version`, `X-App-Build`,
`X-App-Platform` (`RequestContext.kt`). Бекенд (middleware для запитів застосунку) пише їх у
`personal_access_tokens` (нові колонки `app_version`, `app_build`, `app_platform`) — лише коли змінились.
- Токен входу = встановлений застосунок на пристрої; там уже є `last_used_at`, з якого рахується стовпець
  «Застосунок» у списку водіїв. Push-токен більше не потрібен для версії (зараз без увімкненого push версії немає).
- Токен без версії (стара A або B до цього релізу) = «застаріла, версія невідома».

**3. Віджет «Зв'язок з водіями»** на Головній (`constants/dashboardConfig.js`, дозвіл `drivers`):
- Активні водії = статус ≠ `inactive` (`Driver::scopeActive`).
- **Без Telegram** (не `isTelegramConnected()`), двома групами (користувач 10.11):
  - «заявку згенеровано, не підключився» — є `telegram_connection_token` (прострочене посилання — з позначкою);
  - «заявку не генерували» — токена немає.
- **Застосунок:** «не встановлено» — жодного токена входу; «застаріла» — найсвіжіший токен водія з build < останнього:
  версія, ОС, «відстає на N релізів».
- Списки з переходом до картки водія; лічильники в заголовку.
- API: `GET /dashboard/driver-connections` → сервіс `DriverConnectionsReport`.

**4. Тести:** запис релізу (ключ, без дублю), запис версії з заголовків, підрахунок відставання, віджет.

## Відкриті питання

- ~~Що таке «застаріла версія»~~ → **нижча за останню** (10.11, користувач); показувати, на скільки нижча
  за номером (напр. на скільки збірок/версій відстає).
- ~~Остання окремо для iOS/Android~~ → ні: версії iOS і Android синхронізовані, «остання» — одна (10.11, користувач).
- Остання версія = збірка, відправлена на прод; її записує в суперпарк сам скрипт заливки в стори (10.11, користувач).
- Глибший аналіз — пізніше (користувач).
- Telegram: у коді 3 правила (фільтр списку — лише Telegram ID; бейдж — ID + підключення до бота; мобільний — лише
  підключення). Віджет бере правило бейджа; вирівняти фільтр — окремо (не в цій задачі).
- ~~«Активні»~~ → статус ≠ inactive (користувач 10.11).
