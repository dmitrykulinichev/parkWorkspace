# Ідея: майданчик пошуку водіїв для парків-клієнтів (+ окремий домен для сторінок парків)

Записано 2026-11-18 на прохання власника (обговорення під час маркетингового дослідження, `workspace/! marketing`).
Статус: **ідея, повернемося пізніше**. Нічого не вирішено й не почато.

## Суть
Почати не з відкритого каталогу оренди авто, а з майданчика вакансій водіїв **для наших клієнтів**:
парк у g24 одним натисканням публікує «шукаємо водія», а відгуки водіїв падають у кабінет парку.
Пізніше, якщо спрацює, сторінки можна відкрити для всіх парків як безкоштовний «вхід» у g24
(каталог оренди авто під таксі → продаж програми на його сторінках).

## Чому саме так (з обговорення)
- Користь одразу: шукати водіїв мусять усі (на 2026-11-18: 628 вакансій «таксі» на OLX, сотні на Work.ua/Robota.ua).
- Ризиків мало: лише наші клієнти → без чужих оголошень, шахраїв із заставами, модерації.
- Дані вже є в g24: авто, умови (відсоток / оренда / застава), графіки, **реальний дохід водіїв з Uklon** →
  вакансію можна згенерувати автоматично, і «середній дохід водія за місяць — підтверджено g24» не покаже ніхто з конкурентів.
- Відкритий каталог — другий крок (конкуренти: Orenda.taxi — каталог + CRM, до 2 авто безкоштовно, UA+PL;
  маркетплейс оренди Bolt vehicle.bolt.eu; OLX; Telegram-дошки до 11 тис. підписників).

## Слабке місце
Трафік водіїв. Старт без власного трафіку: вакансія з g24 → публікація в міські Telegram-дошки / OLX / Work.ua
(генератор тексту + посилання на сторінку парку з формою), власна аудиторія накопичується з часом (SEO «робота в таксі <місто>»).

## Що вже є в коді
- Публічна сторінка парку: `GET /p/{slug}` (`App\Http\Controllers\Public\ParkLandingWebController`, Blade `landing.show`),
  новини парку `/p/{slug}/news`, API `GET /public/park/{slug}` + `POST /public/park/{slug}/register` (`ParkLandingController`,
  `landing_settings` у `Park`) — самостійна реєстрація водія (див. `workspace/plans/driver-self-registration-plan.md`).

## Окремий домен для сторінок парків (власник: «схоже, її треба переробляти на окремий домен»)
Зараз сторінка живе на домені застосунку. Для майданчика / каталогу, найімовірніше, потрібен окремий публічний домен
(нейтральний бренд для водіїв, SEO, не змішувати з кабінетом). Відкриті питання:
- назва/домен (бренд для водіїв, не «g24»?), структура URL: `<домен>/<місто>/<парк>` чи піддомени;
- що лишається на домені застосунку (кабінет), а що переїжджає (публічні сторінки, новини, форма заявки);
- редіректи зі старих `/p/{slug}`; SEO (sitemap, мета, мікророзмітка JobPosting);
- як «вакансія» пов'язана з наявною формою реєстрації водія.

## Як перевірити попит до розробки
У перших розмовах з лідами питати «де шукаєте водіїв і скільки це коштує» (питання вже в чернетках для №417 Friendly
і №518 «BOLT, автопарк», `workspace/! marketing/registry/contacts.csv`). Ідеї з обговорення: генератор вакансії,
підтверджений дохід, бот кандидатів із воронкою «відгукнувся → співбесіда → вийшов на лінію», реферальна програма водіїв.
